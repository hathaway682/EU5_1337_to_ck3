## cul_ 人名无本地化：删原版覆盖块 + 补新世界中文（01:20-01:45）

- 现象：中文下人名大量显示 `cul_xxx` 原始 key。根因两层：① `common/culture/name_lists/00_generated_name_lists.txt`（Ck3MapGen v0.96 产物）里 64 个块 key 与原版 CK3 name_list 同名（`name_list_french` / `name_list_danish` …），覆盖了原版名字池；② `gen_debug/_gen_cultures_zh_loc.py` 的 `resolve()` 只认 `name_eu5_` 前缀，`cul_*` 一律返回 `("", "?")`，既不写入也不进缺失清单（`FAMS` 不含 `?`），静默漏掉。
- 类 A 已落地：`gen_debug/_drop_vanilla_name_list_overrides.py` 删掉 64 个与原版重名的块（块数 2088 → 2024）。删后原版同名块生效；唯一引用方 `bobo` 文化指向原版 `name_list_bobo`，无悬空。
- 类 B 已落地：`gen_debug/_fill_cul_zh_new_world.py` 按 `_culture_classification.csv` 的 `continent ∈ {北美洲,南美洲,大洋洲,非洲}` 且 `baronies > 0` 选范围（1372 个文化），给 6785 个 `cul_` 键补中文：216 条取 EU5 官方中文（`character_names_dynamic_l_simp_chinese.yml` 的 `name_<slug>`），6569 条用英文原值（拉丁转写，不音译）。`gen_cultures_l_simp_chinese.yml` 11479 → 18264 行。
- 判据工具：`gen_debug/_map_culture_continents.py`（EU5 `map_data/definitions.txt` 顶层 continent → location，配 mod province history 的 culture 与 landed_titles 的 `b_` → province id，输出 `_culture_continents.csv`）。definitions.txt 解析**必须处理「同一行既有 `{` 又有 `}`」**（province 行的 location 列表），否则只抓到 11372/28576 个 location。
- 遗留未动：① 129 个不与原版重名、也无人引用的孤儿 name_list 块（含 1570 个孤儿 `cul_` 键）；② 删块后英文本地化里 1045 个 `cul_` 键变成孤儿；③ 亚洲/欧洲新文化的 `cul_` 键仍未补中文（不在本次范围）；④ 英文值本身有坏项（`cul_a_ccinataratippan: "A_ccinataratippan"`，EU5 复合名被整体 slug 化）。
