## 家族复用分析（EU5 mod vs CK3 原版）

**任务**：分析 EU5 mod 中哪些家族可以直接复用 CK3 原版家族定义。

### 关键前提

mod 与 vanilla 用两套不同 dynasty ID 体系：
- mod 在 `common/dynasties/zz_eu5_dynasties.txt` 用**命名 key**（如 `borjigin_dynasty`），name 字段是 `xxx_dynasty` 或 `name_xxx`
- vanilla 用**数字 ID**（如 `11100`），name 字段是 `dynn_XXX`
- mod 角色用 `dynasty = borjigin_dynasty` 引用，vanilla 用 `dynasty = 11100`
- 所以"复用"= 把 mod 自定义那份删掉、改用 vanilla 数字 ID

- CK3 原版 dynasty 总数：4214
- mod dynasty 总数：1272

C 类典型：mod 用 picard/tuscan/gascon，vanilla 用 french/italian/occitan（CK3 文化树分层，vanilla 家族定义覆盖整棵树，仍可复用）。

## 修复：进游戏后家族名变 dynn_adam（15:13 用户报）

**诊断方法**：读 CK3 的 error.log（在 `D:/Documents/Paradox Interactive/Crusader Kings III/logs/error.log`，不是 C 盘）。

**两个致命错误**（都是归并脚本产生的）：

1. **`common/dynasty_houses/zz_eu5_merged_houses.txt` 第 7 行有 `l_english:/n`**
   - 这是从本地化文件误抄进 common 脚本的非法语法
   - error.log：`Error: "Unexpected token: =, near line: 8"`，然后 **168 个 house 全部 `Unexpected token`** → 整个文件失效
   - 修复：删掉该行

   - `dynasty = house_xxx` 会让 CK3 去找一个叫 house_xxx 的 **dynasty**，找不到 → fallback `dynn_adam`
   - 修复：1781 处 `dynasty = house_` → `dynasty_house = house_`

**验证结果**：house 168 个定义齐全、parent 全部有效、角色 1781 个 dynasty_house 引用全部有定义、5522 个未合并 dynasty 引用有效、无旧写法残留、花括号平衡。

**备份**：`_backup_fix_house_20261018_152213/`

**待用户重启验证**：如果名字仍异常，下一步是把 house 的 name 从 `xxx_dynasty` 改成 vanilla 的 `dynn_XXX`（101 个已有现成 key，59 个需新建）。

**经验教训**：
- 生成 common 脚本文件时绝不能混入本地化 header（`l_english:`）
