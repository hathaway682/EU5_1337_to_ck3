## 统计口径教训：EU5 等级 ≠ CSV 的 `eu5_tier`，CK3 实际头衔 ≠ `ck3_key`

- 用户问「多少 EU5 伯爵级国家在 CK3 升到公国级」，我连续错了几轮，根因都在数据源：
  1. **`eu5_ck3_title_map.csv` 的 `eu5_tier` 列**——与 EU5 真实 rank 有 9 处不符：8 个罗斯公国（DRU/NRK/PNK/POK/RZH/TPS/TUV/VBK）被记成 `c`（实为 `d`），LIT 记 `d`（实为 `k`）。
  2. **`ck3_key` / `ck3_tier` 列**——不反映实际持有：荷兰 `ck3_key` 是空、勃兰登堡是 `c_mittelmark`，但 `d_holland` / `d_brandenburg` 的 `1337.4.1` holder 就是它们的 ruler。
  3. **只看 ruler 的最高头衔**——会把联统国 ruler 的主头衔（PRO 的 `k_naples`、LUX 的 `k_bohemia`）算成它自己的，也会把同一 ruler 的联统小国（ALL/SOR/HAI/ZEE/ORE/BLL）全算进来。
- **正确口径**：EU5 真实等级看 `eu5_politics.json` 的 `countries[tag]["rank"]`；CK3 只看「**该国自己的**公国头衔」：
  - `_grant_landed_duchies.compute()` 的 `grants`（公国 → tag 归属，`why` 为 `same name` / `control N/M`）；
  - 且该公国在 `history/titles/` 的 `1337.4.1` holder == 该国 `ruler`；
  - 联统国（同一 ruler 统治、自己没有对应公国）不算。
- **结果**：EU5 `rank=c` 共 430 个，自己拥有公国级头衔的 **9 个**：
  - BRA 勃兰登堡 → `d_brandenburg`（同名）、HOL 荷兰 → `d_holland`（同名）、PRO 普罗旺斯 → `d_provence`（同名）
  - FCB 弗朗什‑孔泰 → `d_franche_comte`（控制 3/3）、FRI 弗里西亚 → `d_friesland`（控制 3/5）、HTR 荷尔斯泰因‑伦茨堡 → `d_holstein`（控制 1/2）、TIR 蒂罗尔 → `d_tirol`（控制 3/5）
  - PAV 帕维亚 → `d_commune_pavia`、SIE 锡耶纳 → `d_commune_siena`（`common/landed_titles/zz_eu5_communes.txt` 里的公社公国，holder 即本国 ruler，`_grant_landed_duchies` 不收录这类）
  - **排除**：ALL 阿尔施泰特、SOR 卢萨蒂亚、HAI 埃诺、ZEE 泽兰、ORE 奥列舍克、BLL 布永——`d_allstedt`/`d_lusatia`/`d_hainaut`/`d_zeeland`/`d_oreshek`/`d_bouillon` 均不存在，只是被同一 ruler 联统在别人的公国下。
  - LUX 的 `k_bohemia`、PRO 的 `k_naples` 都是别人的王国；PIS 比萨是自己的 `k_pisa`，属王国级（1 个）。
- 教训：**凡「某国在 CK3 是什么等级」的统计，必须用「该国自己的头衔」（grants + holder == ruler），不能用 ruler 的最高头衔，也不能用 title_map 的 `ck3_key` / `eu5_tier` 列。**
